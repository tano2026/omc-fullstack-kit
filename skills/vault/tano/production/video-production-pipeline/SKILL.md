# Video Production Pipeline

Build and run a multi-step content production pipeline: script generation → image prompts → TTS audio → FFmpeg render → Telegram publish.

## Brand System Layer

Before the pipeline runs, every vertical needs a brand identity. This ensures intro, body, outro, and thumbnail are visually consistent.

### ⚠️ AI-Gen Intro Watermark Check

Intro/outro/thumbnail assets generated by AI tools (Google Gemini/VEO, Runway, Pika, etc.) often carry **third-party watermarks or logos**:
- **VEO (Google Gemini):** Encoder metadata = `Google`. Logo watermark typically in bottom-right corner of last 1-2 seconds.
- **Runway Gen-2/3:** Overlaid watermark throughout.
- **Pika Labs:** Bottom-right corner logo.

**BEFORE using any AI-gen intro/outro in the pipeline, verify:**

1.  **Quick check — FFprobe encoder tag:**
    ```
    ffprobe -v error -show_entries format_tags=encoder -of default=noprint_wrappers=1 intro.mp4
    ```
    If `encoder=Google`, the video was generated by Google VEO and carries a logo.

2.  **Visual check — extract sample frames from end:**
    ```
    ffmpeg -i intro.mp4 -vf "select='gte(t,4)'" -vframes 5 -vsync vfr preview_%03d.png -y
    ```

**Fix options (priority order):**

| Option              | Method                                                      | Quality   | Effort |
|---------------------|-------------------------------------------------------------|:---------:|:------:|
| **Crop last 1-2s**    | `ffmpeg -i intro.mp4 -t $DUR -c copy intro_clean.mp4`       | Lossless  | Easy   |
| **Overlay brand logo** | FFmpeg `overlay` filter with brand watermark at same corner | Good      | Medium |
| **Black box mask**    | `drawbox=x=W-w-10:y=H-h-10:w=200:h=40:color=black@1:t=fill` | Blocky    | Easy   |
| **Regenerate**      | Rebuild intro with Remotion (no AI gen tool)                | Best      | High   |

**PITFALL — Don't rely on cropping alone if watermark is in the middle:** Some tools (Runway) place watermarks across the entire video, not just edges. For those, only Remotion rebuild solves it cleanly.
**PITFALL — Metadata check is not enough for all tools:** Runway doesn't always set a detectable encoder tag. Always visually inspect frames from the end of the video.
**PITFALL — Brand logo overlay positioning:** If overlaying your brand logo, use the SAME corner as the watermark to cover it, but offset slightly. Ensure contrast: dark watermark → use your light logo or vice versa.

### Brand JSON — `brand/{vertical}/brand.json`

Single source of truth for all visual elements. Every tool reads this file:

**⚠️ PACK.md ↔ brand.json sync:** When colors change in brand.json, update `domain-packs/{vertical}/PACK.md`'s `Design Tokens` line to match. `content_gen.py` reads PACK.md for the LLM prompt (color + style description), so an outdated PACK.md causes the LLM to generate scripts with wrong visual instructions. If brand.json says green `#1a6b3c` but PACK.md still says blue `#0A66C2`, the content pipeline produces mismatched assets.

### Remotion — Animation Components (`brand/{vertical}/remotion/`)

Remotion renders intro/outro/thumbnail as React components. Components read brand.json for colors/fonts.

**Setup:**
```bash
mkdir -p brand/{vertical}/remotion/src
cd brand/{vertical}/remotion
# package.json with deps: react, remotion, @remotion/cli
npm install
```

**Key components:**
| Component    | File            | Description                                                                                             |
|--------------|-----------------|---------------------------------------------------------------------------------------------------------|
| `<Intro />`    | `src/Intro.tsx`   | 3.5s animation: radial gradient bg → logo scale-in (0→1) → tagline fade → title slide-up |
| `<Outro />`    | `src/Outro.tsx`   | 5s: logo fade → CTA spring animation → social handle                                        |
| `<Thumbnail />` | `src/Thumbnail.tsx` | Still: background image → dark overlay → brand badge top-right → title + gold accent line |

**Animation patterns (Intro):**
- Logo: `interpolate(frame, [0, 45], [0, 1])` — scale from 0 to 1 in 1.5s
- Tagline: `interpolate(frame, [15, 45], [0, 1])` — fade in after logo starts
- Title: `interpolate(frame, [30, 70], [60, 0])` — slide up 60px + fade
- Background: radial gradient with decorative blur circles

**Animation patterns (Outro):**
- Logo: `interpolate(frame, [0, 30], [1, 0.3])` — fade out
- CTA: `spring({ frame: frame-15, config: { damping: 12 }})` — spring bounce
- Social: `interpolate(frame, [45, 75], [0, 1])` — fade in at end

**Rendering:**
```bash
cd brand/{vertical}/remotion
npx remotion render src/index.tsx Intro out/intro.mp4     # 3.5s
npx remotion render src/index.tsx Outro out/outro.mp4      # 5s
npx remotion still src/index.tsx Thumbnail out/thumbnail.png
```

**Static assets:** Logo and sample images go in `public/` directory, referenced via `staticFile()`.

⚠️ **PITFALL — Node modules in browser bundle:** Do NOT import `fs`, `path`, or other Node.js modules in Remotion components. They are bundled for the browser (Chrome headless). Pass data via input props or inline import JSON.

### English Explainer Video Production (Specific Workflow)

This workflow is specifically for producing English-language YouTube explainer content, contrasting with the general GMSP pipeline. It emphasizes a particular voice, visual style, and content format.

#### When to Use

Use this workflow when producing English-language YouTube explainer content with:
-   **Voice:** Primary: **GuyNeural (en-US-GuyNeural)** — warm male, authoritative, exposé/explainer voice. This is the canonical voice and should not be switched unless explicitly requested. Fallbacks: JennyNeural (female, colleague-vibe), EricNeural (deeper, financial gravitas). **NOT SteffanNeural** or AndrewNeural.
-   **Format:** Long-form (8-14 min), 7 scene types (Hook Card, Comparison Split, Savings Bar, Feature Grid, Price Card, Receipt/Evidence, Chapter Card), ~2,000-2,500 words voiceover.
-   **Visual style:** Either:
    *   **Warm/beige:** Hand-drawn, Patrick Hand font, #fdfdfb background, red accent #d92b2b (whiteboard style — for approachable topics).
    *   **Dark/modern:** Dark #0f172a background, white/light text. Accent color is topic-dependent (e.g., blue #2563eb for exposé/aviation/tech, red #ef4444 or green #22c55e for health/finance, red #FF4444 for general explainer). Exactly 1 accent element per scene.
-   **No BGM** — voiceover only.
-   **No real photos or screenshots** — illustration / animated explainer based.
-   **Persona:** Insider who works in the industry, "friend explaining to friend" or "I'm breaking this story."

#### Pipeline (8 Steps)

1.  **Audience Research (MANDATORY)**: Before writing, conduct thorough research on pain points, content trends, misconceptions, competitors, hook psychology, SEO, and trust signals. Save findings to `research/us-audience-research.md`. This drives content direction.
    *   **Channel Name Decision Gate**: If naming isn't final, conduct channel name research focusing on availability, competitor patterns, and name breadth. Propose ranked options.
    *   **Master Content Taxonomy**: Compile a complete content taxonomy, classifying series into Core, Expansion, Low Priority, and Deep Dive tiers. Title each series and provide a total count and priority recommendation.
    *   **Sub-Niche Expansion Analysis**: Evaluate proposed sub-niches (e.g., airline hacks) based on overlap with core, existing competitors, market size, moat potential, and content pillars. Prioritize integration accordingly.
    *   **Competitor Tier Analysis**: Before writing, perform a full market audit, classifying competitors into Giants, Faceless Automation, and Education/Explainer tiers. Output to `research/<channel>-market-audit.md` with analysis and a content pillar plan.
2.  **Format Decision Gate**: Default to Long-form (10-12 min) for YouTube explainers.
    *   **Visual Format — Three Options**: When undecided, present a minimal and an animated version for comparison. The preferred approach is **HTML Animated (Hybrid)** with CSS entrance animations for staggered reveals. For long scenes, add secondary animations. **HTML Slides (Static, Rapid)** is deprecated. HyperFrames is an alternative for multi-layer animations.
    *   **HTML Slides Production**: Create single HTML file with `<div class="slide">` per scene. Screenshot with Playwright, calculate scene durations, generate FFmpeg concat file, and render with FFmpeg.
3.  **Script Writing (Dual-Model Pipeline)**: R1 (DeepSeek R1) writes the first draft, and Claude (stronger model than Sonnet 4) verifies factual claims using a 5-point checklist. Always save R1 output to `scripts/script_r1.md` immediately. Use per-scene word counts in the prompt for R1 to avoid truncation. The R1 script voice should be investigative-satire.
    *   **Format A — Exposé/Reveal**: 8-section structure (Hook, Setup, Bait, Switch, Reality, Bigger Game, How To Beat It, Outro).
    *   **Format A — Enhanced 11-Scene Script Archetype**: For premium content, use an 11-scene pattern with named case studies, regulatory proof points, specific numbers, 4-item list patterns, and specific next-episode teasers.
    *   **Format B — Explainer/Deep Dive**: 11-scene structure (Hook, Myth, Real System, How It Happens Live, Behind the Scenes (GDS), ATPCO Filing, Price Gouging or Math?, Insider Timing, Hotel Room Analogy, Summary, CTA + Cliffhanger).
4.  **Voiceover Generation**: Use GuyNeural (en-US-GuyNeural) for English explainers. For scripts >2,000 words, split into segments and concat with FFmpeg. Verify duration with ffprobe.
5.  **Figures Generation**: Use Pollinations for scene figures, then upscale with FFmpeg.
6.  **Compose index.html**: Update `index.html` with scene data and composition sources. Each scene composition follows the DESIGN.md style guide.
7.  **Render + Verify**: Use HyperFrames to render compositions. Verify video+audio streams and duration after rendering with ffprobe.
8.  **Delivery**: Send to Telegram (if <20MB) or compress with FFmpeg.

#### Motion Graphics Explainer Format — Time-Driven Animation (Preferred)

This approach uses a **JS animation loop that reads `dataset.time`** on the root element, instead of CSS `animation-delay`. It's the **only reliable approach** for frame-by-frame capture.

**Scene Type Library (7 types)**: For rapid demos, use a 4-scene condensed arc (Hook Card, Comparison Split, Receipt/Evidence, Punchline + CTA). For full-length videos, expand using the full library of 7 scene types.

**Pacing Rules**: Change visual every 8-12s, no scene over 18s. Use a 3-phase arc per video: Expose → Compare → Punchline.

**HTML Structure Pattern**: Use `div` elements with `.phase1`, `.phase2`, `.phase3` classes for phase transitions.

**Rendering: Time-Driven JS Animation Loop**: Use a JS animation loop to decouple animation timing from wall-clock speed. This is more precise and reliable than CSS `animation-delay`.

**Capture script — Playwright screenshot sequence**: Use Playwright to capture frames at a set FPS, then compile to video with FFmpeg.

**Key Insight**: MutationObserver works with frame-by-frame capture by setting `dataset.time` to the *intended* frame time, allowing the JS `animate()` function to compute the correct visual state instantly.

#### Pitfalls

-   **Language discipline**: When discussing an English-language YouTube channel, always respond in English.
-   **Writing from instinct without research**: User will reject scripts written without audience research.
-   **Static slides rejected**: Default to hybrid animated HTML for first-time format tests.
-   **Animation alone is not enough**: Content must also be exceptional.
-   **"Làm mẫu" means full production**: Deliver a complete video, not a stub.
-   **135s no man's land**: Expand scripts to 8-12 min for long-form explainers, don't cut to 60s.
-   **AndrewNeural vs GuyNeural**: Always use GuyNeural for English explainer channels.
-   **FFmpeg NOT available on this Windows machine**: Use Hermes `text_to_speech` with pre-split scripts or download FFmpeg portable.
-   **Edge TTS splitting**: Scripts >5,000 chars will fail as one-shot. Split by scene, gen each, concat.
-   **Edge TTS .ogg output**: Edge TTS outputs `.ogg` files; use the `.mp3` copy for FFmpeg concat.
-   **Chapter labels**: Add a `.chapter` class to each slide with uppercase, small font, letter-spaced, and brand accent color.
-   **Animation re-trigger hack**: For Option B, force DOM reflow to re-play CSS animations.
-   **HyperFrames rendering on first-run**: Expect longer render times initially.
-   **Red accent rule**: Exactly 1 red element per scene.
-   **Memory near-full on this machine**: Keep renders manageable.
-   **No BGM**: User prefers cleaner audio without background music.
-   **File:// URL path on Windows**: Playwright requires `file:///D:/path` format for Windows paths.
-   **Statistical claims need cited sources**: Every number should have a real-sounding source.
-   **Edge TTS timing on Windows**: Communicate API works reliably for scripts up to 10,000 chars.

## Multi-Agent Content Production Architecture

This section describes the multi-agent architecture for long-form video content production, which is designed to scale and manage complex workflows from research to publishing.

### AI Agency Model (v2.0, tháng 7/2026)

The core of this architecture is an **AI Agency** model, where a One-Person Company operates using 7 distinct roles across 3 runtimes. This model enables the agent to handle diverse tasks and projects, with ABTRIP being just one example of a job running on this infrastructure.

#### 7 Roles — 3 Runtimes

| # | Role                | File trong kho                        | Runtime       | Vai trò trong pipeline    |
|:--:|---------------------|---------------------------------------|---------------|---------------------------|
| ① | **Research & Data**   | `agents/research-pro.md`              | Hermes        | Gather data, verify claims|
| ② | **Marketing**       | `agents/company/roles/marketing.md`   | Hermes + OpenClaw | Chiến lược kênh, schedule |
| ③ | **Sales**           | `agents/sales-ceo/system-prompt.md`   | Hermes + OpenClaw | Outreach, báo giá          |
| ④ | **Content Creator** | `agents/company/roles/content-creator.md` | Hermes        | **Viết script** = pipeline cũ's Content Writer |
| ⑤ | **Dev & Automation** | 3 playbooks (Hermes/OpenClaw/Antigravity) | Cả 3          | Hạ tầng, pipeline, automation |
| ⑥ | **Designer**        | `agents/company/roles/designer.md`    | Hermes + OpenClaw | Ảnh, visual, brand tokens  |
| ⑦ | **Media**           | `agents/company/roles/media.md`       | Hermes + OpenClaw | **Production pipeline** = render + publish |

#### Domain Pack Pattern (thay cho pipeline-riêng-theo-project)

Mỗi content vertical / project = 1 file `domain-packs/<slug>/PACK.md`. Lõi agent không đổi, chỉ cắm pack là chạy.

**Cách nạp role:**
1. Fetch role pack từ kho: `fetch("agents/company/roles/content-creator.md")`
2. Fetch Domain Pack: `fetch("domain-packs/giai-ma-so-phan/PACK.md")`
3. Embed cả 2 vào delegation message → agent hành xử theo role đó

#### Content Production Pipeline (cho Media role)

```
SCRIPT (từ Content) → STORYBOARD → VISUALS (Designer) → POST-PRODUCTION (Media) → CEO OK → PUBLISH
```

**Pipeline 4 bước cho Media role:**
1. **Pre-production**: Script (từ Content Creator) → storyboard/shotlist → asset planning
2. **Production**: Ảnh AI (Imagen/Fal) · Video gen · Voiceover (Resona TTS)

#### fetchKho — Truy xuất kho GitHub

```python
import urllib.request, json, base64, os

def fetch(path):
    req = urllib.request.Request(
        f"https://api.github.com/repos/tano2026/AI-Vibe-Toolkit/contents/{path}",
        headers={"Authorization": f"token {os.environ['GITHUB_TOKEN']}",
                 "Accept": "application/vnd.github.v3+json"}
    )
    data = json.loads(urllib.request.urlopen(req).read())
    return base64.b64decode(data["content"]).decode()
```

GITHUB_TOKEN lấy từ Windows Credential Manager: `git credential-manager get` với protocol=https, host=github.com.

Workflow chuẩn: `fetch("KHO-INDEX.md")` → map kho → `fetch("agents/HERMES-PLAYBOOK.md")` → `fetch("domain-packs/[slug]/PACK.md")` → thực thi.

#### Layer 1: Research Agent
- **Input**: Topic domain, target audience
- **Output**: TopicBrief + EpisodePlan list (hook, angle, series structure)
- **Key**: Không research quá sâu — chỉ cần đủ context để Content Writer bám vào
- **Tools**: web_search để validation, LLM để synthesis

#### Layer 2: Content Writer — "Trùm Content"
- **Input**: Topic brief + episode parameters
- **Output**: Full script with frame breakdown
- **Storytelling built-in**: PAISA, Hero's Journey, 3-Act, Circle of 5
- **7 nguyên tắc vàng** (xem references/storytelling-system-prompt.md)

#### Layer 3: Frame Planner
- **Input**: Script with frames
- **Output**: Production frames + HTML composition + VTT subtitles
- **Frame scaling** (xem references/frame-scaling-reference.md)

#### Layer 4: Orchestrator
- **Input**: Topic, duration, series count
- **Output**: Full production output (HTML + audio plan + VTT + YouTube metadata)
- **CLI pattern**: `python orchestrator.py {brainstorm|full|series}`

#### Layer 5: YouTube Marketing (NEW — automatic)
- **Input**: Script dict from Content Writer
- **Output**: `metadata.json` with SEO title (3 variants), description + timestamps, 15 tags, thumbnail brief, community post, TikTok hook, 3 Shorts ideas
- **$0 cost**: Pure LLM-generated, no API key needed
- **Integration**: Auto-runs as Phase 5 after frame export in `cmd_full`

#### Harness Layer (NEW — resilience)
- **ProgressTracker** (agents/harness.py): Checkpoint persistence per phase — resume if pipeline crashes mid-way
- **VerificationLoop** (agents/verify.py): 11 quality checks split across script (6) and frames (5) — frame count ≥ min, narration length, hook/cliffhanger presence, duration consistency, visual prompt completeness
- **Auto-retry**: Script phase retries up to 3x with exponential backoff if verification fails

### Key Design Decisions

#### Why 4 agents instead of 1 big script?
- **Separation of concerns**: mỗi agent chuyên 1 domain
- **Cost control**: dùng LLM nhỏ (Haiku) cho research, LLM lớn (Sonnet) cho content
- **Parallelism**: research chạy cùng lúc với production prep
- **Testing**: mỗi agent test độc lập

#### Storytelling > Production

### Implementation Steps

1. **Create `agents/llm.py`**: Shared provider wrapping OpenRouter API (DeepSeek default, Gemini Flash fallback). Read API key via regex from Hermes `config.yaml` at runtime. Export `write()` (returns str), `structured()` (returns dict), `fast()` functions.

   **CRITICAL CONTRACT — `structured()` returns `dict`, NOT `str`**: All callers treat the return value as a dictionary with `.get()` method. If `structured()` returns a string, every caller crashes. The function must: call `json.loads()` internally, strip markdown code fences, fall back to regex extraction `re.search(r"\{.*\}", text, re.DOTALL)`, and return `{"error": "parse_failed", "raw": text[:500]}` as last resort. NEVER return a raw string.

   **Retry pattern**: Wrap every API call in exponential backoff (3 attempts, 2^attempt seconds delay). OpenRouter and DeepSeek have transient rate-limit and timeout failures.

   **Key validation**: Validate API key at client creation time, not on first API call. Raise `RuntimeError` immediately if key is empty.

2. **Create `agents/research_agent.py`**: TopicBrief + EpisodePlan dataclasses, brainstorm function với system prompt. Call `llm.structured()` — NOT `llm.write()` — because it needs dict output.

3. **Create `agents/content_writer.py`**: EpisodeScript dataclass, write_episode function với storytelling system prompt. MUST include robust `_extract_basic_script` fallback for non-JSON model output (DeepSeek etc.). Use `llm.write()` (text mode) for episode generation since DeepSeek ignores `response_format=json_object` — then parse frames from free-text output.

   **MUST import `os`** if using `os.path.exists()` anywhere — missing this causes `NameError` at runtime.

4. **Create `agents/frame_planner.py`**: Production frame export (HTML tương thích render pipeline + VTT). Clean unused imports — if `structured` is imported but never used, remove it to avoid confusion.

5. **Create `agents/orchestrator.py`**: CLI entry point with argparse. Sanitize all Vietnamese-derived path segments:
   ```python
   safe_topic = re.sub(r'[^\w\s-]', '', topic).strip().replace(' ', '-')[:40]
   ```

   **MUST import `from dataclasses import asdict`** — `asdict()` is called in `asdict_safe()`. Add **empty-list guards** before every `briefs[0]` access:
   ```python
   if not briefs:
       print("❌ No topics generated. Aborting.")
       return
   topic = briefs[0]
   ```

   Use `asdict_safe()` for safe serialization of mixed dict/dataclass lists:
   ```python
   def asdict_safe(obj):
       if isinstance(obj, dict): return obj
       try: return obj.__dict__
       except AttributeError:
           try: return asdict(obj)
           except Exception: return {"value": str(obj)}
   ```

6. **Create `agents/harness.py`**: ProgressTracker class with checkpoint persistence:
   - `save_checkpoint(phase, data)` — writes JSON checkpoint

   - Phases: `research → script_gen → frame_plan → export`

## Loop Optimization with Harness Engineering

The agent pipeline (Research → Content Writer → Frame Planner → Production) runs sequentially by default. For reliability at scale, apply Harness Engineering patterns:

### Verification Loop (per-agent)

```
Agent completes output ──► Validate output ──► [PASS] → next agent
                                  │
                           [FAIL] ↓
                            Retry (max 3)
                                  │
                           [FAIL x3] → escalate
```

Each step's verification:
- **Research Agent**: Validate TopicBrief has hook + angle and isn't empty
- **Content Writer**: Validate EpisodeScript has total_frames >= required minimum and each frame has narration >= 50 words
- **Frame Planner**: Validate HTML compiles (check file existence and structure)
- **Production**: Validate output file exists and has no corrupted frames

## Pitfalls

- **Model JSON mode not universal**: DeepSeek via OpenRouter ignores `response_format=json_object`. Use `llm.write()` (text mode) instead of `structured()`, then parse frames from free-text output. The fallback parser in `content_writer._extract_basic_script` handles multiple patterns: Frame N: markers, JSON key-value lines, paragraph chunking, and regex-based narration extraction. Always assume the model may NOT produce valid JSON — build robust text fallback.
- **OpenRouter key extraction**: Hermes masks API keys in terminal output. To read the OpenRouter key from `config.yaml`, encode with `base64.b64encode()` for transport, then decode at destination. Never print or echo the raw key — it gets masked. The `llm.py` read-from-config approach is safest: the key never appears in logs.
- **Windows path sanitization**: Vietnamese characters (ơ, ư, ê, đ, à, etc.) crash `os.makedirs()` on Windows. Always sanitize topic-derived path segments: replace non-word characters, then truncate to 40 chars. Do NOT use `.lower().replace(' ', '-')` directly on raw Vietnamese strings.
- **Frame count vs quality**: More frames does not mean better content. 48 frames with weak script still produces a weak video.
- **Agent context window**: Long scripts (45p = 48 frames = ~9600 words) fit in most LLM contexts, but the prompt must be tight. Token waste from loose instructions causes hallucinations.
- Audio generation bottleneck: 48 frames x 55s = 44 minutes of TTS. Use async edge-tts or a queue system to avoid blocking the pipeline.
- **`write()` arg order**: `llm.write(system=..., prompt=...)` — NOT `write(prompt, system=...)`. Python passes the first positional arg to `system`, then the keyword arg `system=...` is a duplicate → `TypeError: got multiple values for argument 'system'`. Always use keyword args explicitly.
- **`import re` inside functions shadows global**: If a function has `import re` anywhere in its body (even deep in a phase block), Python treats `re` as a *local* variable for the **entire function**. Any use of `re` before that line raises `UnboundLocalError`. Fix: move all `import re` to the top of the file alongside other imports.
- **`dotenv.load_dotenv()` needed for .env keys**: Python's `os.environ` does NOT read `.env` files automatically. If API keys (like `RESONA_API_KEY`) are stored in `~/.hermes/.env`, add `from dotenv import load_dotenv; load_dotenv(os.path.expanduser("~/.hermes/.env"))` early in the entry point script.
- **PowerShell >> appends UTF-16 LE**: When the user runs `echo KEY=value >> .env` from PowerShell, the file becomes UTF-16 LE with null bytes between characters. Python's `dotenv` and any UTF-8 reader crashes with `embedded null character`. Fix: read raw bytes with `open(env, 'rb')`, find the `R\x00E\x00S\x00...` patterns, extract and decode the UTF-16 block, then rewrite the whole file as clean UTF-8.
- **Resona TTS Phase 6 pattern**: Integration reads `RESONA_API_KEY` from env (via dotenv), formats each frame's `narration` field with `Speaker 1:` prefix, chunks by ~1800 chars to stay under the 2000-credit limit, submits each chunk as a separate async job (poll every 2s for ~60s), then merges all chunk MP3s with FFmpeg concat filter: `ffmpeg -i c1.mp3 -i c2.mp3 -filter_complex '[0:a][1:a]concat=n=2:v=0:a=1[out]' -map '[out]' merged.mp3`. Wrap in try/except so TTS failure never blocks the pipeline.
- **HTML size**: 48 frames x ~500 bytes = ~24KB HTML. OK for headless Chrome, but test frame count limits before production — GSAP timeline length is the real constraint.
- **Verification != trust**: Never blindly pass agent output to the next step. Validate frame count, narration length, and JSON structure before proceeding. A bad script that looks structurally valid is harder to catch than a crashed pipeline.
- **YouTube Marketing wrapped in try/except**: SEO generation uses LLM and can fail without breaking the core pipeline. Always wrap in try/except: `generate_metadata()` failure → warning message, pipeline continues.
- **`_dict_to_episodescript` function name collision**: When adding helper functions between `asdict_safe()` and `cmd_series()`, ensure they have distinct names. A patch that accidentally renames `_dict_to_episodescript` to `cmd_series` creates two competing definitions — the second silently shadows the first. Lint doesn't catch this because both are valid Python.
- **`content_writer._extract_basic_script` import `os`**: If the function calls `os.path.exists()`, it MUST have `import os` at the file top-level. Without it, Python raises `NameError: name 'os' is not defined` at runtime but the module imports successfully (lazy evaluation).\
- **Establish structure BEFORE production**: Never produce a video without first creating the Domain Pack (`PACK.md`) and topic library (`<slug>.topics.json`). The "chốt luồng trước khi sản xuất" principle: 3 verticals share 1 channel but need distinct brand voice, design tokens, and topic libraries. Generate 25-30 topics minimum per vertical before rendering.\
- **LLM structured() timeout for large scripts**: DeepSeek V4 Flash via OpenRouter takes ~120-180s to generate a 29-frame, 20-min script with 16K max_tokens. Set terminal timeout ≥ 200s or use `background=True` + `notify_on_complete=True` to avoid timeout errors.\
- **FFmpeg Windows: zoompan `n` variable undefined**: On Windows FFmpeg 8.1.1, the `zoompan` filter's `n` (frame count) variable raises `Undefined constant or missing '(' in 'n'`. Use `st` (time in seconds) or avoid zoompan entirely — use `trim=duration=N` + `concat` filter for image-to-video rendering instead. Exit code `4294967274` = `STATUS_INVALID_PARAMETER` on Windows — indicates a malformed filter expression, not FFmpeg being broken.\
- **FFmpeg image slideshow on Windows**: For rendering static images into a video, the most reliable Windows approach is: `-loop 1 -i img.png -filter_complex "[0:v]trim=duration=246,setpts=PTS-STARTPTS[v0]"` then concat. Avoid `xfade` when dealing with more than 2 segments — the PTS arithmetic gets complicated and frequently frequently produces wrong durations. Simple `concat` filter is more robust.

- **FFmpeg 20+ min video — the PROVEN approach (raw H.264 binary concat)**: All concat methods (concat filter, concat protocol, MPEG-TS) fail past 207s on Windows FFmpeg 8.1.1. The only approach that reliably produces full-duration output for 15-45 min videos:

  **Step 1 — Render each segment as raw H.264 Annex B:**
  ```bash
  ffmpeg -y -loop 1 -r 24 -t 246 -i segment.png \\
    -c:v libx264 -preset veryfast -crf 24 -pix_fmt yuv420p \\
    -bsf:v h264_mp4toannexb -f h264 seg1.h264 \\
    -loglevel error -stats
  ```
  Use `-bsf:v h264_mp4toannexb -f h264` to force Annex B byte-stream output (needed for binary concat).

  **Step 2 — Binary concat (no ffmpeg):**
  ```bash
  cat seg1.h264 seg2.h264 seg3.h264 seg4.h264 seg5.h264 > combined.h264
  ```
  Works because Annex B H.264 uses start codes (00 00 00 01) as sync markers.

  **Step 3 — Mux audio with explicit `-t DURATION` (NEVER `-shortest`):**
  ```bash
  ffmpeg -y -i combined.h264 -i voiceover.mp3 \\
    -c:v copy -c:a aac -b:a 128k -t 1189 \\
    -pix_fmt yuv420p no_subs.mp4 \\
    -loglevel error -stats
  ```
  CRITICAL: Use `-t DURATION_IN_SECONDS`, NOT `-shortest`. Raw H.264 has no container timing metadata, so `-shortest` cannot determine video duration and silently drops audio. Get duration from audio file: `ffprobe -v quiet -show_entries format=duration -of json voiceover.mp3 | python -c "import sys,json; print(json.load(sys.stdin)['format']['duration'])"`.

  **Step 4 — Embed subtitles as track (no re-encode, fastest):**
  ```bash
  ffmpeg -y -i no_subs.mp4 -i subs.srt \\
    -c:v copy -c:a copy -c:s mov_text \\
    -metadata:s:s:0 language=vie \\
    output.mp4 -loglevel error -stats
  ```
  Video + audio copied without re-encode. Player offers subtitle toggle.

  **Step 4b — Burn subtitles into video** when soft subs aren't an option:
  ```bash
  ffmpeg -y -i no_subs.mp4 \\
    -vf "subtitles=subs.srt:charenc=UTF-8:original_size=1920x1080:force_style='FontName=Arial,FontSize=54,PrimaryColour=&H00FFFFFF,OutlineColour=&H00000000,BorderStyle=1,Outline=1,Shadow=0,MarginV=60,Alignment=2'" \\
    -c:v libx264 -preset veryfast -crf 24 \\
    -c:a aac -b:a 128k \\
    -t 1189 -pix_fmt yuv420p \\
    output.mp4 -loglevel error -stats
  ```
  BorderStyle=1 (outline) NOT BorderStyle=3 (box). BorderStyle=3 creates a background box that fills the screen. Netflix style = outline only, thin (Outline=1), no shadow (Shadow=0). Speed is ~0.4-1.2x (15-30 min for 20-min video).

  - **`time=00:03:25.06` display artifact**: During `-c:v copy` on raw H.264, FFmpeg may show `time=00:03:25.06` in stats even when frame count matches full duration. Cosmetic display bug - ignore. Validate with: `ffprobe -v quiet -show_entries stream=index,codec_name,codec_type -of csv output.mp4` + check frame count matches expected frames (duration_seconds * fps).

#### Base Video Generation

3. **Render loopable segment** (avoids drawtext timeout):

   ```bash
     -i hyperframes/assets/branding_overlay.png \
     -i hyperframes/assets/intro_card.png \

   # Loop to desired duration (concat method)
   for i in $(seq 1 <N>); do echo "file 'epXX_segment.mp4'"; done > concat_segments.txt
   ffmpeg -y -f concat -safe 0 -i concat_segments.txt -c:v libx264 -preset ultrafast -crf 25 -c:a copy -t <duration> epXX_base.mp4
   ```

   **Pitfall**: Do NOT use `-c copy` on concat-loop base videos — it produces corrupt H.264 NAL units. Always re-encode with `-c:v libx264`.

4. **Voiceover (from user)**: Place in `tts/voiceover_gap6.mp3`
5. **Swap audio**: `ffmpeg -y -i epXX_base.mp4 -i tts/voiceover_gap6.mp3 -c copy -map 0:v -map 1:a -shortest epXX_raw.mp4`

### 4. Final FFmpeg Render
Single command: base + 7 chapter overlays + voiceover → final MP4.

**Timing calculation:**
Gap starts = end of each section:
- Gap 1: end of 01_hook
- Gap 2: end of 02_boicanh + 6s
- Gap 3: end of 03_tuvi + 12s
- …(each subsequent gap = 6s later)

Each overlay has fade-in (0.5s), hold (~4.5s), fade-out (1s) for 6s total window.

```bash
ffmpeg -y \
  -i "base.mp4" \
  -i "tts/voiceover.mp3" \
  -i "hyperframes/chapters/chapter_1.png" \
  ... \
  -i "hyperframes/chapters/chapter_7.png" \
  -filter_complex "\
    [0:v]trim=0:<total_duration>[base]; \
    [2:v]format=rgba,fade=t=in:st=0:d=0.5:alpha=1,fade=t=out:st=5:d=1:alpha=1,setpts=PTS-STARTPTS+<gap1>/TB[ch1]; \
    ... \
    [base][ch1]overlay=0:0[t1];[t1][ch2]overlay=0:0[t2];...;[t6][ch7]overlay=0:0[vout]" \
  -map "[vout]" -map "1:a" \
  -c:v libx264 -preset ultrafast -crf 28 \
  -c:a aac -b:a 128k -shortest -movflags +faststart \
  "/tmp/epXX_final.mp4"
```

### 5. Compress for Telegram
```bash
ffmpeg -i "/tmp/epXX_final.mp4" \
  -vf "scale=1280:720" \
  -c:v libx264 -preset fast -crf 35 \
  -c:a aac -b:a 48k -movflags +faststart \
  -maxrate 400k -bufsize 800k \
  "/tmp/epXX_720p.mp4"
cp "/tmp/epXX_720p.mp4" "D:/epXX_final.mp4"
```

### Pitfalls

#### HyperFrames render timeout (>600s)
HyperFrames rendering a 465s+ composition can timeout. **Fix:** Render base once (ep01_base_v3.mp4), reuse for all episodes by trimming with FFmpeg. Only re-render if layout/branding changes.

#### Chapter overlay setpts timing
The `setpts=PTS-STARTPTS+<gap_start>/TB` expression is critical. Wrong timing = chapter text appears at wrong moment. Always calculate from actual MP3 durations + gap sums, not from script word count.

#### Telegram upload failure
Files >20 MB often timeout. Always compress to 720p CRF 35 (~6-9 MB for 8-min video). Copy to `D:\` (no spaces in path) before sending. If that still fails, use CRF 38 and `maxrate 300k`.

#### No BGM rule (strict)
User explicitly rejected BGM after uneven volume in mixed sections. **Voiceover only** — clean, no background music whatsoever.

#### Edge TTS pitch variation via rate
On Edge TTS, simulate pitch by varying `--rate`:

| Emotion                               | Rate          | Perceived effect            |
|---------------------------------------|:-------------:|-----------------------------|
| Trầm/bi quan (story scenes)           | `+5%` to `+8%` | Lower, slower, heavier      |
| Bình thường                           | `+16%`        | Default pace                |
| Cao trào / hào hứng (climax, CTA) | `+22%` to `+25%` | Higher, faster, energetic   |

**Edge fail:** Text quá ngắn (< 40 chars) → NoAudioReceived. Fix: thêm text vào segment trước đó hoặc nối thêm 1 câu dummy.
